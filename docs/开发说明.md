# 开发说明

本文说明 QQ聊天记录管理器的代码结构、必须遵守的设计约束，以及测试、构建和发布流程。

## 目录

| 位置 | 内容 |
|---|---|
| `main.py` | 程序入口（保留 `multiprocessing.freeze_support()`，冻结程序的采样子进程依赖它） |
| `qqarchive/` | 程序代码 |
| `tests/` | 自动化测试，全部使用合成数据 |
| `scripts/` | 构建、发布、验收、性能基准和 GitHub 发布脚本 |
| `installer/` | Inno Setup 安装脚本与中文语言文件 |
| `docs/releases/` | 每个版本对外公开的更新报告 |

## 程序结构

| 层次 | 主要模块 |
|---|---|

| 取钥与密钥 | `winmem.py`（只读进程内存）、`keyscan.py`（按数据库盐定位并用第 1 页认证）、`keystore.py`（DPAPI 保存）、`key_lifecycle.py` |
| 归档 | `store.py`（归档库、搜索、覆盖范围）、`importer.py`（单事务导入、合并去重、冲突变体）、`merge.py`、`recovery.py`、`package.py`、`exporters.py` |
| 来源与流程 | `discovery.py`、`sources.py`、`official_backup.py`、`auto.py`、`profiles.py`、`avatars.py`、`media.py` |
| 手机 | `adb.py`（只读命令）、`media_pull.py`（分块、断点续传、校验） |
| 迁移监测 | `transfer_core.py`、`transfer_monitor.py`、`transfer_process.py`（独立采样子进程）、`transfer_tcp.py` |
| 界面 | `desktop.py`（主窗口）、`workflows.py`（导入流程）、`search_window.py`、`chat_windows.py`、`chat_actions.py`、`chat_tools.py`、`session_tree.py`、`session_delegate.py`、`search_delegate.py`、`chrome.py`（自绘窗口与动画）、`dialogs.py`、`smooth_scroll.py` |
| 自检 | `dialog_checks.py`、`interaction_checks.py`、`transfer_checks.py`、`transfer_performance.py` |

## 设计约束

**数据安全**
- 对 QQ 数据库、备份和手机只读。不要在来源读取相关模块里加入任何写入路径。
- 密钥、日志、异常信息和报告中不得出现完整密钥。
- QQ 官方备份容器在取得并认证独立密钥、验证表结构之前保持“暂不支持导入”（`sources.UnsupportedSource`），不得改成可导入，也不得写入未经验证的密钥派生方法。
- 导入在单个事务中完成，取消或失败必须整批回滚。

**搜索与索引**
- 索引 `ix_msg_conv_sender_time` 在新建归档库时创建。已有归档库只能由启动后可取消的后台任务（`MainWindow.ensure_search_index`）补建，不能放进每次打开都会在界面线程执行的建表脚本。
- 1–2 个字的关键词无法使用 trigram 全文索引，全局搜索在分组查询中保持 `NOT INDEXED` 顺序扫描。
- 搜索相关的性能改动须用 `scripts/bench_search.py` 的合成库做前后对比。

**界面**
- 数据读取在后台线程或独立只读连接中进行，界面线程不做网络、文件扫描或长查询。
- `FramedDialog` 只让显式标记的默认按钮（`AnimatedButton.setDefault`）响应回车。标题栏在窗口首次显示时才创建，不要恢复 Qt 的隐式默认按钮，否则输入框里按回车会关闭窗口。
- 所有可滚动列表接入 `SmoothScroll`。
- 搜索窗口的已选发送人由 `ChosenDelegate` 绘制：条目数据保存完整文字，只在绘制时缩短昵称，QQ 号和“×”不得被省略。
- 透明度效果只能用于覆盖层，不要直接加在滚动视口上。

## 测试

```bash
.venv\Scripts\python.exe -m pytest -q
```

界面测试使用离屏平台。做 100%/150%/200% 三档缩放检查时，`QT_QPA_PLATFORM=offscreen:configfile=<文件>` 中的配置文件路径必须是相对当前目录的纯 ASCII 路径，并配置足够大的离屏屏幕（例如 2560×1440）。

## 构建与验收

1. `scripts/build_v<版本>.ps1 -Compiler <ISCC.exe 的绝对路径>`：先跑全部测试，再用 PyInstaller 打包、做冻结程序自检，并编译安装包。Windows PowerShell 5.1 会丢弃空字符串参数，因此必须显式传入编译器路径。
2. `scripts/frozen_acceptance.py <暂存目录>`：在三档缩放下对冻结程序做离屏验收（弹窗、交互、迁移监测、发送人名单），并做七页面截图和迁移监测持续响应测试。
3. `scripts/installer_qa.py --stage <暂存目录> --version <版本>`：用独立的 AppId 和目录做完整安装验收，包括首次安装、文件哈希、重复升级、配置升级、快捷方式和卸载后数据保留。
4. `tests/installer_adb_checks.py --root . --output <新目录> --version <版本>`：ADB 组件被占用时的升级检查。
5. 生成已验收文件清单后，用 `release_v<版本>.py --publish-existing <暂存目录>` 发布。已发布的版本不可覆盖。

版本号规则：补丁为 `vX.Y`，新功能为 `vX+1`。

## 发布到 GitHub

本地发布时加 --publish-github 会自动运行 `scripts/github_publish.py --version <版本>`，也可以手动运行。它会：

1. 检查 `docs/releases/v<版本>.md`：只允许“新功能”和“修复”两节；
2. 把这份更新报告加到 `CHANGELOG.md`；
3. 扫描待提交文件、更新报告和解包后的程序文件。规则包括密钥、令牌、用户目录路径，以及只保存在本机、不进仓库的 `.local/release.json` 中的隐私特征。有任何命中就停止，不会提交；
4. 提交、打版本标签、推送，并创建 GitHub Release，上传安装包、便携版与完整资产包，正文就是更新报告。完整资产包包括公开源码、说明与 SHA-256 清单；上传前复核源码快照和包内文件。

更新报告只写面向用户的新功能和修复，不写修改过程、本机路径或个人数据。提交身份使用 GitHub 提供的匿名邮箱（`…@users.noreply.github.com`），脚本会拒绝其他邮箱。仓库采用 `.gitignore` 白名单，私人笔记、用户数据、构建产物、发布目录和第三方工具都不会被提交。


# QQ 历史补全

## 使用

1. 按 [NapCat 官方安装说明](https://napneko.github.io/guide/boot/Shell)安装并登录自己的 QQ。软件不内置 NapCat，不修改 QQ 的数据库，也不代替账号登录。
2. 在 NapCat 建立 HTTP 服务端：绑定 127.0.0.1、消息格式 array、设置访问令牌。勿将 WebUI 管理端口作为消息接口端口。[配置说明](https://napneko.github.io/config/basic)
3. 在本软件选择“导入 → 补全 QQ 中可查看、但本地缺失的历史”，填写归档账号、HTTP 地址及令牌，验证账号。
4. 选择群聊或私聊、号码、开始和结束时间。日期输入精确到秒，边界包含；每页默认请求 20 条，可调整到 100 条；每次默认最多 2000 页。网络失败重试时会逐步缩小每页数量。
5. 开始后，从接口当前可返回的最新消息向前读取；消息按页提交。窗口可隐藏至底部，取消会暂停，之前已提交的页面保留。
6. 同一账号、会话和日期范围点击“开始 / 继续”会恢复断点。“重新检查”从最新消息重新遍历，但不会删除已归档消息。接口重启后若旧临时标识不可用，可重新检查。
7. 已存在的附件原址引用。勾选需要下载的附件类型后，再下载 QQ 返回的受支持链接；附件可单独重试，重新检查可刷新过期链接。正文不依赖附件下载成功。取消附件下载后重试从该文件开头重新下载。

## 状态解释

- 已遍历至开始时间之前：仅表示接口返回的消息跨过时间边界，不证明其中没有缺失。
- 空页、重复页、方向异常：停止并保留断点，之前的历史仍未验证。可在 QQ 中打开这段历史，再重试或重新检查。
- 账号不一致、消息格式错误：停止该页，整页不提交，断点不会跳过问题页。
- 待补齐附件：可能尚未下载、接口没有提供链接，或该类型未被勾选。
- 附件失败：可能是失效链接、文件不可读、摘要不一致或超过单文件 2 GB 限制。

缺少 QQ 原始序号时只保留来源内的保守身份标识；跨来源相似消息标为疑似重复，不按文字相同直接吞并。内容冲突保留为变体。界面中的读取数量包含分页重叠消息，新增数量才是新归档的记录数。

## 设计与验证方案

链路：连接及账号校验 → 限定会话和时间 → 有界分页 → 校验整页 → 原子提交消息和断点 → 独立附件队列 → 汇总未验证状态。

消息正文在联网完成后才进入数据库事务，避免等待网络时占用写锁。成功提交的消息、来源记录、全文索引与当前断点属于同一事务；异常与取消回滚当前页。接口连续失败最多尝试三次，页数预算与重复页检测防止无限读取。

原始数据库导入继续使用现有读取模块。本功能复用公开的消息接口格式独立实现适配，不打包第三方源码；使用 get_login_info、get_group_msg_history、get_friend_msg_history，转发查看另用 get_forward_msg。只访问用户填写的本机接口，令牌不写入软件配置、任务记录或日志。附件网络访问只接受支持的 QQ HTTPS 域名，并检查重定向、摘要、长度和文件大小。

自动验证覆盖：真实本机 HTTP 往返（合成消息）、账号切换、分页重叠、同秒边界、空页与重复页、格式错误整页回滚、断点和全文索引一致性、跨来源合并、未知类型保留、取消、附件原址引用与下载限制，以及原生窗口前置步骤和重复导入。

真实云端可用性需要单独实测：选一个已知缺失的会话和时间段，对比 QQ 加载前后的接口结果，并在归档中核对原消息。自动测试不能代替这项核对。官方加密手机备份解码、直接读取未 Root 手机私有数据库和实时新消息订阅不属于本功能。

# 读取转发记录中的 QQ 号

在聊天记录中双击已识别的合并转发卡片，或右键选择“查看转发内部记录 / QQ 号”。新窗口不锁定主界面。

## 正文来源

- 本地已有完整转发正文：直接显示。
- 已有 OneBot / NapCat 导出的转发 JSON：点击“读取正文 → 打开转发 JSON”。支持完整接口响应、messages 列表和自定义 node 列表；也可打开原始卡片 JSON，取得资源标识后继续读取。
- 只有转发卡片：需要可选的 NapCat HTTP 服务，登录账号必须与该归档账号一致。填写本机地址（例如 http://127.0.0.1:3000）和访问令牌，点击“从 QQ 读取”。程序不包含、也不会自动安装 NapCat。普通 QQ 本身不提供这个 HTTP 地址。
- 旧归档没有资源标识：可选择“从原库补读卡片”，提供当时的 nt_msg.db。使用程序已验证的密钥，只定位这条原消息，校对会话与时间，不复制数据库。原库被 QQ 占用或字段格式不支持时会说明原因；不会自动结束 QQ。

QQ 号来自子消息明确提供的发送者字段；仅有 UID 时尝试使用当前归档账号下唯一匹配的本地资料。无法匹配时显示未知，不从昵称、头像、正文数字或转发者号码推测。自定义转发可填写身份字段，这些信息不能单独证明真实作者。

## 查看与保存

左侧选择发送者，顶部按 QQ 号、昵称或内容搜索本层记录；每页最多 100 条。右键人物头像可复制号码或查看本地资料。双击嵌套转发进入下一层，“返回上层”保留筛选和滚动位置。缺失时间显示未知。

成功读取的转发正文保存到当前数据目录的 forwards 子目录，原始 JSON 和数据库保留原址。内部消息独立保存，不增加接收群的消息数，也不会据此建立共同群聊关系。普通全局聊天搜索与归档导出暂不包含该独立缓存；转移这部分数据时需同时保留 forwards 目录。图片、语音等以类型提示展示，本版不下载转发内部附件。

接口仅接受 localhost / 127.0.0.1 / ::1，忽略代理，不跟随重定向；访问令牌不进入配置或缓存。取回正文有超时、大小与嵌套层数限制，失败不覆盖已有结果。

## 验证范围

解析与界面使用合成数据验证；HTTP 流程使用隔离的本机测试服务。未用用户真实 QQ 转发完成兼容性验证，不保证过期、未缓存或缺少身份字段的所有记录都可读取。
