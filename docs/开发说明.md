# 开发说明

本文说明 QQ聊天记录管理器的代码结构、必须遵守的设计约束，以及测试、构建和发布流程。

## 目录

| 位置 | 内容 |
|---|---|
| `main.py` | 程序入口（保留 `multiprocessing.freeze_support()`，冻结程序的采样子进程依赖它） |
| `qqarchive/` | 程序代码 |
| `tests/` | 自动化测试，全部使用合成数据 |
| `scripts/` | 构建、发布、验收、性能基准和 GitHub 发布脚本 |
| `installer/` | Inno Setup 安装脚本与中文语言文件 |
| `docs/releases/` | 每个版本对外公开的更新报告 |

## 程序结构

| 层次 | 主要模块 |
|---|---|
| 来源读取 | `sqlcipher.py`（逐页 HMAC 认证与解密、WAL 解析）、`cipherdb.py`（只读虚拟文件系统）、`btree.py`（只读表读取）、`ntqq.py`（NT 消息表与消息体解析）、`protobuf.py` |
| 取钥与密钥 | `winmem.py`（只读进程内存）、`keyscan.py`（按数据库盐定位并用第 1 页认证）、`keystore.py`（DPAPI 保存）、`key_lifecycle.py` |
| 归档 | `store.py`（归档库、搜索、覆盖范围）、`importer.py`（单事务导入、合并去重、冲突变体）、`merge.py`、`recovery.py`、`package.py`、`exporters.py` |
| 来源与流程 | `discovery.py`、`sources.py`、`official_backup.py`、`auto.py`、`profiles.py`、`avatars.py`、`media.py` |
| 手机 | `adb.py`（只读命令）、`media_pull.py`（分块、断点续传、校验） |
| 迁移监测 | `transfer_core.py`、`transfer_monitor.py`、`transfer_process.py`（独立采样子进程）、`transfer_tcp.py` |
| 界面 | `desktop.py`（主窗口）、`workflows.py`（导入流程）、`search_window.py`、`chat_windows.py`、`chat_actions.py`、`chat_tools.py`、`session_tree.py`、`session_delegate.py`、`search_delegate.py`、`chrome.py`（自绘窗口与动画）、`dialogs.py`、`smooth_scroll.py` |
| 自检 | `dialog_checks.py`、`interaction_checks.py`、`transfer_checks.py`、`transfer_performance.py` |

## 设计约束

**数据安全**
- 对 QQ 数据库、备份和手机只读。不要在来源读取相关模块里加入任何写入路径。
- 密钥、日志、异常信息和报告中不得出现完整密钥。
- QQ 官方备份容器在取得并认证独立密钥、验证表结构之前保持“暂不支持导入”（`sources.UnsupportedSource`），不得改成可导入，也不得写入未经验证的密钥派生方法。
- 导入在单个事务中完成，取消或失败必须整批回滚。

**搜索与索引**
- 索引 `ix_msg_conv_sender_time` 在新建归档库时创建。已有归档库只能由启动后可取消的后台任务（`MainWindow.ensure_search_index`）补建，不能放进每次打开都会在界面线程执行的建表脚本。
- 1–2 个字的关键词无法使用 trigram 全文索引，全局搜索在分组查询中保持 `NOT INDEXED` 顺序扫描。
- 搜索相关的性能改动须用 `scripts/bench_search.py` 的合成库做前后对比。

**界面**
- 数据读取在后台线程或独立只读连接中进行，界面线程不做网络、文件扫描或长查询。
- `FramedDialog` 只让显式标记的默认按钮（`AnimatedButton.setDefault`）响应回车。标题栏在窗口首次显示时才创建，不要恢复 Qt 的隐式默认按钮，否则输入框里按回车会关闭窗口。
- 所有可滚动列表接入 `SmoothScroll`。
- 搜索窗口的已选发送人由 `ChosenDelegate` 绘制：条目数据保存完整文字，只在绘制时缩短昵称，QQ 号和“×”不得被省略。
- 透明度效果只能用于覆盖层，不要直接加在滚动视口上。

## 测试

```bash
.venv\Scripts\python.exe -m pytest -q
```

界面测试使用离屏平台。做 100%/150%/200% 三档缩放检查时，`QT_QPA_PLATFORM=offscreen:configfile=<文件>` 中的配置文件路径必须是相对当前目录的纯 ASCII 路径，并配置足够大的离屏屏幕（例如 2560×1440）。

## 构建与验收

1. `scripts/build_v<版本>.ps1 -Compiler <ISCC.exe 的绝对路径>`：先跑全部测试，再用 PyInstaller 打包、做冻结程序自检，并编译安装包。Windows PowerShell 5.1 会丢弃空字符串参数，因此必须显式传入编译器路径。
2. `scripts/frozen_acceptance.py <暂存目录>`：在三档缩放下对冻结程序做离屏验收（弹窗、交互、迁移监测、发送人名单），并做七页面截图和迁移监测持续响应测试。
3. `scripts/installer_qa.py --stage <暂存目录> --version <版本>`：用独立的 AppId 和目录做完整安装验收，包括首次安装、文件哈希、重复升级、配置升级、快捷方式和卸载后数据保留。
4. `tests/installer_adb_checks.py --root . --output <新目录> --version <版本>`：ADB 组件被占用时的升级检查。
5. 生成已验收文件清单后，用 `release_v<版本>.py --publish-existing <暂存目录>` 发布。已发布的版本不可覆盖。

版本号规则：补丁为 `vX.Y`，新功能为 `vX+1`。

## 发布到 GitHub

本地发布完成后，发布脚本会自动运行 `scripts/github_publish.py --version <版本>`，也可以手动运行。它会：

1. 检查 `docs/releases/v<版本>.md`：只允许“新功能”和“修复”两节；
2. 把这份更新报告加到 `CHANGELOG.md`；
3. 扫描待提交文件、更新报告和解包后的程序文件。规则包括密钥、令牌、用户目录路径，以及只保存在本机、不进仓库的 `.local/release.json` 中的隐私特征。有任何命中就停止，不会提交；
4. 提交、打版本标签、推送，并创建 GitHub Release，上传安装包和便携版，正文就是更新报告。

更新报告只写面向用户的新功能和修复，不写修改过程、本机路径或个人数据。提交身份使用 GitHub 提供的匿名邮箱（`…@users.noreply.github.com`），脚本会拒绝其他邮箱。仓库采用 `.gitignore` 白名单，私人笔记、用户数据、构建产物、发布目录和第三方工具都不会被提交。
